# 5주차 회고

## 주제 선정

이번 5주차 과제의 주제는 **계산기**였다.  
처음 노션 문서를 봤을 때 직접 계산기를 동작해볼 수 없어서 이해가 어려웠다.  
그래서 **iPhone 기본 계산기의 디자인과 기능을 최대한 똑같이 구현**해보기로 했다.

심플한 UI지만 내부 로직은 생각보다 많이 복잡했다.  
특히 iPhone 계산기에서는 **AC 버튼과 ⌫(뒤로가기) 버튼이 동일한 위치에 토글되는 구조**인데,  
이 방식이 불편하다고 느껴져서 **상단에 AC 버튼, 하단에 ⌫ 뒤로가기 버튼**을 따로 배치했다.

### iPhone 계산기의 버튼 구성

- **숫자 버튼**: 숫자 입력
- **AC 버튼**: 모든 값 초기화 (0)
- **% 버튼**: 나머지 연산자 (`9 % 4 = 1`)
- **÷ 버튼**: 나누기 연산자
- **× 버튼**: 곱하기 연산자
- **- 버튼**: 빼기 연산자
- **+ 버튼**: 더하기 연산자
- **= 버튼**: 계산 결과 출력
- **. 버튼**: 소수점 입력 (중복 입력 방지)
- **+/- 버튼**: 현재 값의 부호 반전 (`3 → (-3)`, `-5 → 5`)
- **⌫ 버튼**: 마지막 숫자 삭제 (`123 → 12`, `1 → 0`)

> ※ `+/-` 버튼과 `⌫` 버튼은 아직 구현하지 못했다.

---

## 마크업 (HTML)

- 수식(`formula`)과 결과(`result`)를 각각 `<div>`로 분리해 **두 개의 표시 영역** 구성
- 각 버튼에는 역할별 클래스를 부여해 **기능 구분을 명확히 함**
  - `.number`
  - `.operator`
  - `.function`
  - `.equal`
  - `.backspace`

---

## 스타일링 (CSS)

- 전체 레이아웃은 **Flex와 Grid를 조합**해 정렬
- 버튼 색상은 iPhone 계산기를 참고해 설정
  - 연산자 버튼: **주황색**
  - 기능 버튼(AC 등): **회색**
  - 숫자 버튼: **진한 회색**

---

## 동작 (JavaScript)

- 상태 관리를 위해 다음과 같은 변수 사용
  - `currentInput`: 현재 입력 중인 숫자
  - `expression`: 수식 표시 영역에 보여질 수식
  - `finalizedFormula`: 계산 완료 후 고정되는 수식
  - `justEvaluated`: `=` 버튼이 눌린 직후 상태 여부
- 연산자가 연속 입력될 경우, **마지막 연산자를 새 연산자로 교체**
- `×`, `÷` 기호는 `*`, `/`로 치환하여 `eval()`을 사용해 계산
- **소수점 중복 입력 방지 로직** 구현

## 느낀 점

> 사실 이번 과제의 JavaScript는 대부분 AI의 도움을 받았다.  
> 이미 계산기로 스타일링까지 마친 상태였고, 중간에 주제를 바꾸는 것도 쉽지 않았다.  
> 노션을 봐도 이해가 가지 않았고, 아직 이런 로직을 스스로 구현할 실력은 부족하다고 느꼈다.  
> 그럼에도 과제는 무조건 제출해야 한다는 성격이라, 어떻게든 완성해냈다.

> JS로 로직을 직접 짜려는 순간, 머릿속이 하얘지고 손이 멈춰버렸다.  
> 주석으로 '무엇을 구현해야 하는지'만 써두고, 한참 동안 멍하니 화면만 바라봤다.  
> 그래도 직접 짜지는 못하더라도, **코드를 읽고 이해할 수 있는 힘**은 기르고 싶다.

> 다음엔 `⌫` 버튼과 `+/-` 기능도 구현해보고 싶다.

> 그리고 이번 과제가 마지막 JS 과제라서 마음이 더 무거웠다.  
> 특히 다음 주부터 시작될 바닐라 프로젝트가 많이 걱정된다.  
> 사람들은 '컴공과 출신이면 그래도 잘하겠지?'라는 고정관념을 갖는 것 같다.  
> 나는 뭘 이끌어갈 실력도, 리더십 있는 성격도 아니라서  
> 나를 잘 이끌어줄 조장을 만나고 싶다.  
> 부족하더라도, **열심히 해보려고 한다.**
